ЗАДАЧА ДЛЯ ОТДЕЛЬНОГО ОКНА VS CODE

Создай отдельный проект Telegram-бота для публикации новостей на нескольких моих сайтах. Первый подключаемый сайт — fxlfm. Этот файл лежит в корне проекта fxlfm и описывает уже подготовленный API сайта. Код бота создай в новой соседней папке/отдельном репозитории, не внутри fxlfm. Работай автономно: реализуй приложение, конфигурацию, инструкции запуска и осмысленные тесты. Не ограничивайся схемой или псевдокодом.

ЦЕЛЬ

Один бот для редакторов. В личном чате редактор нажимает «Создать статью», выбирает сайт, а бот последовательно спрашивает заголовок, краткое описание, основной текст, фото, категорию, при необходимости автора и теги. После этого бот показывает предпросмотр и кнопки «Изменить», «Опубликовать», «Отмена». До подтверждения ничего не публикуется. Длинный текст можно собирать из нескольких сообщений до кнопки «Текст готов». Фото можно пропустить. После публикации бот возвращает ссылку на статью. Процесс можно отменить и продолжить после перезапуска бота.

АРХИТЕКТУРА БОТА

1. Python 3.12, современная поддерживаемая библиотека Telegram Bot API, отдельная база данных для редакторов, черновиков, состояния диалога и результатов публикации. Выбери конкретные зависимости и зафиксируй версии. Для локальной разработки допустима SQLite, для продакшена предусмотрена PostgreSQL или другая надёжная БД. Секреты только в переменных окружения; создай .env.example без настоящих ключей.
2. Отдельные слои: обработчики Telegram, сценарий/состояния диалога, хранилище черновиков, клиент API сайта и адаптер площадки. Сделай интерфейс SitePublisher и реализацию FxlfmPublisher. Добавление сайта с тем же API должно требовать в основном конфигурации, сайта с другим API — нового адаптера без переписывания диалога.
3. Площадки задаются конфигурацией: идентификатор, название, базовый URL API, токен интеграции. Категории и авторов получай с выбранного сайта, не храни их числовые ID как общие для всех сайтов.
4. Доступ к публикации только Telegram user ID из allowlist. Проверяй user ID на каждом действии, включая нажатие старых inline-кнопок. Не полагайся на username. Добавь команду /myid, доступную и без allowlist: она сообщает отправителю только его числовой Telegram user ID и не даёт доступа к публикации. Токены сайтов и Telegram нельзя выводить в лог, отправлять в чат или сохранять в черновике.
5. Сохраняй черновик после каждого шага. Защищай сценарий от сообщений не по порядку, повторных callback, одновременных нажатий и перезапуска процесса. Делай понятные ответы об ошибках с возможностью повторить действие.
6. У каждого черновика UUID external_id, созданный один раз и сохранённый до первой отправки на сайт. При сетевом таймауте повторяй запрос с тем же external_id. После публикации храни article_id, URL, площадку и время. Если редактор редактирует уже отправленный черновик, создавай новую версию с новым external_id и явно показывай, что это новая статья.
7. Для первого релиза можно выбирать один сайт на публикацию. Структура данных должна позволять позднее выбрать несколько сайтов и хранить отдельное состояние доставки для каждого.
8. Для фото Telegram: получи файл через Bot API, проверь размер, скачай его во временное локальное хранилище и передай бинарный файл в API сайта. Не передавай Telegram file URL как image_url статьи. Временный файл удаляй после успешной отправки или отмены. Бот не должен предполагать, что фото обязательно.
9. Реализуй локальный запуск через polling; продакшен может использовать webhook, если настроены HTTPS и проверка секретного заголовка Telegram. Добавь Dockerfile, docker-compose.example.yml или эквивалентные инструкции запуска.

КОНТРАКТ FXLFM, УЖЕ РЕАЛИЗОВАННЫЙ В САЙТЕ

Базовый URL: https://fxlfm.com/api/bot/v1/ (для локальной разработки подставь URL запущенного backend).
Все запросы ниже требуют заголовок Authorization: Bearer <BOT_INTEGRATION_TOKEN>. Это отдельный ключ сайта, НЕ Telegram bot token и НЕ JWT администратора. JSON-запросы отправляй с Content-Type: application/json. Все URL имеют завершающий /.

GET options/
Ответ 200: {"version":1,"site":"fxlfm","categories":[{"slug":"politics","name":"Politics"}],"authors":[{"slug":"...","name":"..."}]}.

POST articles/
Тело JSON:
{
  "external_id": "UUID черновика",
  "title": "Заголовок",
  "content": "Полный текст\n\nВторой абзац",
  "summary": "Краткое описание, необязательно",
  "seo_description": "Необязательно, максимум 320 символов",
  "category_slugs": ["politics"],
  "author_slug": null,
  "tag_names": ["Breaking"]
}
Обязательны external_id, title, content и непустой category_slugs. Остальные поля необязательны. Создаёт только черновик; status в запросе не передаётся. Ответ 201 при создании, 200 при повторе того же external_id с теми же данными, 409 если external_id уже связан с другим содержимым. Ответ содержит external_id, article_id, status, slug, url, image_url.

GET articles/<external_id>/
Возвращает состояние уже созданной статьи. Используй для восстановления после таймаута.

PUT articles/<external_id>/image/
multipart/form-data, поле image с бинарным JPG/PNG/WebP. Максимум 10 МБ и 20 млн пикселей. Сайт переводит фото в JPEG, сохраняет его у себя и возвращает постоянный image_url. Повторная отправка после успешной загрузки возвращает существующее фото. После публикации фото через этот API не меняется.

POST articles/<external_id>/publish/
Публикует сохранённый черновик, возвращает status="published" и url. Повтор безопасен и возвращает уже опубликованную статью. Публикацию вызывай только после подтверждения редактора и после успешной загрузки фото, если оно было выбрано.

Порядок: GET options/ → собрать данные и подтвердить предпросмотр → POST articles/ → при наличии фото PUT image/ → POST publish/ → показать URL. Если шаг завершился таймаутом, GET articles/<external_id>/ и затем безопасно повторить нужный шаг.

Ответы 400 означают неверные поля/файл, 403 — неверный или отсутствующий ключ, 404 — неизвестный external_id, 409 — конфликт UUID или попытку изменить опубликованную статью. Бот должен показывать редактору понятную ошибку, а технические детали писать в лог без секретов. На создание статьи не нужно использовать /api/admin/articles/.

ПРОВЕРКА ГОТОВНОСТИ БОТА

- Есть команды /start, /new, /drafts, /cancel, /myid и понятное меню кнопок.
- Неавторизованный Telegram user ID не может начать или продолжить публикацию.
- После перезапуска можно продолжить незавершённый черновик.
- Можно исправить любое поле до подтверждения.
- Категории приходят с выбранного сайта; выбранный slug уходит в API.
- Повторные Telegram update и сетевые retry не создают дубликаты статей.
- Есть тесты сценария, allowlist, адаптера fxlfm с поддельным HTTP API, повторной публикации и ошибки загрузки фото.
- README содержит запуск, настройку Telegram-бота, переменные окружения, связь с fxlfm и добавление второго сайта.

НАСТРОЙКА FXLFM СО СТОРОНЫ САЙТА

В локальном .env сайта уже создан BOT_INTEGRATION_TOKEN. Возьми его оттуда и укажи такой же в секретах отдельного проекта бота для площадки fxlfm. Не записывай реальный токен в этот текстовый файл, исходный код, логи или git. На новой инсталляции сайта сгенерируй отдельный длинный случайный ключ. SITE_URL должен указывать на публичный адрес сайта, затем перезапусти backend; миграция 0011_bot_integration применяется при старте production compose. Для локального запуска SITE_URL должен указывать на адрес, по которому браузер видит backend и изображения.

ПРИМЕЧАНИЕ ДЛЯ ТЕСТИРОВАНИЯ

Сначала проверь создание черновика, загрузку фото, публикацию и повтор тех же запросов на локальном fxlfm backend. Не публикуй тестовую статью на живом сайте без прямого разрешения владельца.
